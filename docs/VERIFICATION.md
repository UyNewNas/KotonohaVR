### Codex CLI 独立协议验证

本机安装官方 npm 包 **`@openai/codex@0.161.0`**，使用本地假 Responses 端点验证了真实 CLI 的请求形状及完整 JSON 返回路径。执行只读元数据检查后，适配器发出一次模拟文本请求并成功解析 schema 结果，CLI 退出码为 0。

最终适配器在本次默认模型探针中的实际请求 `tools=[]`，输出格式为严格 JSON Schema。未知模型的回退元数据可能保留提问工具描述；额外模拟调用验证该工具在非交互模式不可用，未提供的命令工具也被拒绝。因此结论限于已验证 CLI 版本与隔离配置下的外部工具禁用，不宣称 CLI 永久具有通用零工具模式。没有真实模型推理、付费调用、用户登录操作或读取／复制登录令牌。

适配器限定此已验证版本；Windows 官方 npm 启动脚本的解析使用 Node 参数数组，全程 `shell=False`，对话只走 stdin。Windows 路径处理与超时清理有模拟测试，但 Windows 原生进程行为仍需要本机验证。工具配置和组织策略不兼容时会停止此次请求并给出说明。

## GitHub CI

[工作流与运行记录](https://github.com/UyNewNas/KotonohaVR/actions/workflows/ci.yml) 是远程验证的依据。工作流执行 Linux/Windows 自动测试，随后在 Windows 构建 PyInstaller 应用。检查程序从临时目录启动打包后的 EXE，先验证 Qt、OpenVR、音频采集和本地 ASR 依赖可以加载，再启动离线演示并验证截图和退出码。

构建包内的 `BUILD-INFO.json` 记录构建依赖，`ci-demo.json` 与 `ci-demo.runtime.json` 记录启动与依赖检查结果。检查不初始化音频设备、不连接 SteamVR、不下载识别模型，也不需要模型账号。

具体提交的通过状态、测试日志和可下载构建包，以该提交对应的成功运行记录为准。本地测试通过不等于远程 CI 已通过；Windows 离线启动检查也不等于硬件效果已验证。

## 仍需真机／账号验证的项目

- 用户自己的 GPT API Key、Codex 账号权限、额度、可用模型和真实回答质量。
- Windows WASAPI 与 PyAudioWPatch 的真实播放／麦克风设备，包括 Virtual Desktop 双路音频。
- Quest 3S + Virtual Desktop + SteamVR + VRChat 的真实头显显示、清晰度、控制器姿态与焦点。
- faster-whisper 模型下载、真实语音识别的速度与准确率；本次没有下载语音模型。
- Windows 构建包在用户本机的设备与驱动兼容性。
- 端到端实时延迟、资源占用和多人嘈杂房间效果。本版不承诺具体毫秒数或准确率。

## 完成真机验收的顺序

离线演示 → 真实文字请求 → 已知外语的播放回环 → 中文按住录音 → VR 只读浮窗 → 控制器选择／取消／确认 → 退出并重新启动。

若某一步失败，先保留此前已成功的链路，仅定位该步骤。反馈不需要包含 API Key 或登录文件。
