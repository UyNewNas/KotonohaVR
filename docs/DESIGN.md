# 接口与设计

## 产品约定

应用把“别人实际说的话”“自己准备说的话”“自己确认说完的话”分开处理。候选不是历史，选择也不是发送。本人发言只有在显式确认后进入上下文。

目标语言来自对方音频／原文的识别证据，或用户手动选择。中文准备通道不能更新它。选中的 `PinnedReply` 是不可变快照，后续字幕和建议继续更新时不替换快照。

## 模块之间的数据

语音模块输出 `Transcription(text, language, confidence)`，不在 ASR 阶段先翻译成英语。回复模块因此仍可得知对方原来的语言。

文本模型输入包含 `mode`、`latest_text`、`source_language`、`reply_language`、最近实际 `context`、`style`、`max_words`。`suggest` 模式必须返回三条候选，`custom` 模式必须返回一条忠实翻译。

模型输出：

```json
{
  "source_language": "ja",
  "source_zh": "你愿意和我们一起去下一个世界吗？",
  "reply_language": "ja",
  "summary_zh": "对方邀请你一起去另一个世界。",
  "candidates": [
    {
      "id": "1",
      "intent_zh": "询问去处",
      "text": "次はどのワールドに行くんですか？",
      "meaning_zh": "接下来准备去哪个世界？",
      "reading_hint": ""
    }
  ]
}
```

上面只展示一个候选的结构；正常 `suggest` 返回三条不同意图。除了 JSON Schema，应用再次校验字段、候选数量、重复内容、语言、长度和中文对应字段。不符合契约时不显示不完整选项。

## 并发与生命周期

- 模型调用在后台线程执行，Qt 主线程通过 signal 接收。
- 同一时刻最多一个模型请求执行，另有一个“最新待处理请求”；连续输入合并掉中间待处理项。
- 请求带会话修订与顺序号。新话语、手动语言切换、清空、设置变化使旧结果失效。
- ASR 使用一条工作线程和最多三个待处理片段，避免无限积压。
- 收音使用代次标识；停止、清空和关闭后，旧音频回调与识别结果不能恢复历史。
- 关闭时既检查 worker 发信号前的状态，也检查 Qt 收到已经排队信号后的状态。
- 已经在执行的同步本地推理无法强制中断；其结果会被丢弃。没有声称能够撤回已发出的云端请求。

## GPT

通过 `httpx` 调用 Responses API，使用 `text.format` 严格 JSON Schema，`store: false`，不提供可调用工具。对话正文与风格偏好放入数据输入，不作为开发指令。处理 HTTP 错误、超时、拒绝、不完整输出和错误 JSON，界面错误不显示 Key 或完整响应正文。

## Codex

使用用户本机官方 CLI 的非交互文本调用。CLI 负责身份验证，应用不读取或复制登录令牌。调用在临时空目录完成，不接触用户项目或继承项目指令。

适配器对依赖的 CLI 开关做能力检查；关键隔离能力不存在时提示升级。使用隔离用户配置的调用方式，禁用命令执行、浏览、MCP、应用、插件等外部工具，同时要求临时会话和结构化输出。首版验证使用本地假模型端点检查真实 CLI 发出的请求，不需要真实账号或模型额度。

Codex 的可用登录方式、模型、额度和版本开关以官方 CLI 为准；这不是读取或转售网页登录令牌的接入方式。具体本机 CLI 验证版本与剩余工具限制记录在 `VERIFICATION.md`。

## 音频

Windows 依赖 PyAudioWPatch 枚举 WASAPI 回环与输入设备。输出端点回环不是进程回环；多个应用在同一输出设备上的声音会混在一起。

分句使用能量阈值、预卷、默认 650 ms 停顿和 12 秒上限。不是逐词流式识别，也没有声源分离或玩家身份。麦克风默认关闭，按住启用，松开提交；应用没有控制 VRChat 静音。

本地模型使用 faster-whisper CPU int8，共享模型访问包含生成器消费都受锁保护。云端调用 `/audio/transcriptions`；`whisper-1` 用 verbose JSON，能够提供多语种检测字段的转写模型按其响应解析语言。缺失或混合语言返回未知，不凭空设成英语。

## VR 与平台

Qt 对话面板渲染为 RGBA 纹理，由 OpenVR `IVROverlay` 显示。设置窗口与 Key 字段不在 VR 纹理里。

射线点选以控件的 `vr_action` 属性命中。普通动作要求同一控件按下与松开；录中文动作在按下开始、松开或失去焦点时结束。动作只分发一次，不同时触发额外 Qt click。

使用普通 OpenVR 浮窗，不向 VRChat 注入代码。具体 Virtual Desktop / Quest 手柄映射、追踪姿态、视觉清晰度及输入焦点需要真机验证。

## 后续适合增加的功能

1. Windows 进程回环，减少其他应用声音干扰。
2. 实测后再设计独立手柄快捷动作和更紧凑的头显布局。
3. 带明确授权和可见采集区域的桌面 OCR，复用现有对话与模型接口。
4. 说话人分离与目标交谈者选择，需要处理真实多人混音的限制。
5. 更细的字幕延迟测量与真正的流式 ASR。

这些是后续方向，不属于 v0.1 已实现能力。
