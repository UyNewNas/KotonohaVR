# Windows / Virtual Desktop / SteamVR 使用说明

## 1. 先确认桌面文字链路

使用 GitHub Actions 的 `KotonohaVR-windows-x64` 构建包时，完整解压并保留 `_internal` 目录，双击 `START_DEMO.cmd`。构建包不需要另外安装 Python。从源码运行时，先安装 Python 3.12（64 位，带 Python Launcher），再双击源码目录的同名脚本。

如果能看到三条日语双语候选，说明桌面依赖与基础交互正常。点击第二条，在提词中看到外语和中文意思，再取消或确认读完。

关闭演示。构建包用户运行 `KotonohaVR.exe`；源码用户先运行 `SETUP_WINDOWS.cmd`，再运行 `START_APP.cmd`。进入设置，连接 GPT 或 Codex，使用底部文字输入测试一句外语。先把模型账号、网络和结构化输出问题解决，再开始配置收音。

`START_DEMO.cmd` 强制使用离线固定样例，不会因为以前保存过真实模型配置而产生模型调用。

如果脚本提示找不到 `py -3.12`，请安装对应版本，或者自行用已安装的受支持 Python 创建 `.venv` 后运行命令。推荐 3.12 是本项目的验证目标，不要求卸载其他 Python。

## 2. 配置语音识别

### 本地 faster-whisper

- 语音识别选择“本地 faster-whisper · CPU”。
- 模型默认 `small`，首用由依赖下载并缓存，可能需要较长等待。
- 希望降低本地识别负担可试 `base` 或 `tiny`，准确率需要自己比较。
- 本版固定 CPU `int8`，不自动占用你的显卡显存，也没有附带 CUDA 配置。
- 初次下载模型需要网络；下载完成后 ASR 可以本地运行，回复模型仍按其设置联网。

### OpenAI 语音 API

- 语音识别选择“OpenAI 语音 API”。
- 默认模型 `whisper-1`，通过 `verbose_json` 取得原文语言。
- 填写语音 Key；留空时按顺序使用 GPT Key、`OPENAI_API_KEY`。
- Codex CLI 登录不会自动提供这里的语音 API 凭据。
- 音频通过内存 WAV 发送给配置的语音服务，不写成录音文件。

## 3. 找对两个设备

保持 Virtual Desktop、SteamVR 和 VRChat 已正常工作，然后点击“刷新音频设备”。

**上面的设备框是“别人说话”的来源。** 选择实际输出 VRChat 声音的耳机／扬声器的回环项。回环读取整个输出端点，当前没有按 `VRChat.exe` 隔离：如果浏览器或播放器也向同一设备播放，它们会一起被录入。

**下面的设备框是“自己准备中文”的来源。** 选择能够收到 Quest 3S 麦克风的 Windows 输入设备。Virtual Desktop 的具体设备名称以本机为准，切勿把自己麦克风选成对方通道。

点击“开始收听”后，电平条应随播放声音变化。设备正在使用时，对应下拉框会锁住；要换设备，停止收听或刷新设备。刷新会停止当前两路收音，避免选择的新设备与实际旧流不一致。

如果回环有自己的麦克风监听或系统“侦听此设备”，自己的发言也可能重新进入对方通道。检查 Windows 音频设置和 VRChat/VD 的监听选项，避免这类回路。

## 4. 收听与回答

1. 对方说完一小句后，等待原文、中文翻译与选项。
2. 选一个真正符合你想法的意思。候选只是建议，模型不应替你决定个人事实。
3. 看固定提词，把外语亲口说出来。收到新字幕时，固定提词保持原样。
4. **完整说完**再点击“已完整说完”。如果没有读、只读一部分或改了意思，点“取消”；首版没有自动校验你到底说了多少，也没有 UI 编辑实际发言记录。

要自己想一句中文：

1. 在 VRChat 内静音自己的语音，同时保持 VD 麦克风传输开启。
2. 按住言叶 VR 的“按住说中文”，说完后松开。
3. 等待一条“中文意思 + 对方语言”的候选，点选后查看固定提词。
4. 在 VRChat 内自行解除静音，读外语，再确认读完。

录音中的提示只是提醒，**不是静音状态检测**。超过 12 秒会截断自己的中文，仍在松开按钮时才提交；尽量每次只准备一句话。

## 5. 语言控制

- 默认“自动跟随对方”；本地 ASR 的低置信度结果不会直接当作确认语言。
- 常见的极短回应（如 OK、yes）会尽量保持已有对话语言，避免一次短词就误切换。
- 手动选择语言后锁定回复目标，直到切回自动。
- 自己的中文转写始终属于“准备回答”，不作为对方语言的新证据。
- 多人、混合语种或嘈杂环境可能检测错误；这时先手动锁定语言。

## 6. 在头显里显示

在 SteamVR 已运行时点击“显示 VR 浮窗”。设置提供视野前方、左手、右手，支持宽度和距离。

浮窗绘制的是专用对话面板，账号密码、模型设置、桌面其他窗口不会进入这个面板。桌面“提词预览”可以检查显示内容。

手柄交互依赖 SteamVR 的浮窗射线，实际控制器姿态和 Virtual Desktop 焦点仍需真机确认。开启交互可能临时接管游戏输入；只想看字幕时关闭“手柄点选”。没有提供独立的全局手柄动作绑定。

手部位置依赖对应控制器被 SteamVR 追踪。追踪丢失时浮窗暂时隐藏，并在追踪恢复后重新显示；桌面状态栏会提示。

## 7. 常见问题

| 现象 | 先检查 |
| --- | --- |
| 桌面启动失败 | 构建包需完整解压并保留 `_internal`；源码需检查 Python 3.12 和依赖安装，从终端启动查看错误 |
| “演示不支持这段内容” | 演示只有固定样例，真实文字需先切 GPT/Codex |
| API 401/403 或无模型权限 | Key、服务地址和账户模型权限；不要把网页登录当成 API Key |
| Codex 版本兼容提示 | 本版适配器验证并限定 CLI 0.161.0；可按 README 在项目目录独立安装，不必更改原来的全局 CLI |
| Codex 无回复 | 在终端确认 `codex login`，模型可用；CLI 错误经过脱敏，必要时单独检查官方 CLI |
| Codex 正常但语音报缺 Key | 语音另选本地识别，或填写语音 API Key |
| 本地首次识别一直等待 | 模型可能正在下载／初始化；检查网络与磁盘，不要反复点生成 |
| 电平不动 | 所选回环不是实际播放设备，或播放链路没有声音 |
| 音乐也被翻译 | 本版捕获输出端点混音；关闭背景音乐／把其他应用移到别的输出设备 |
| 队列跟不上 | 换更小的本地模型或云端识别；降低连续长段讲话；应用会提示丢弃过多片段 |
| VR 浮窗打不开 | SteamVR 已启动、`openvr` 已安装、PC 能识别头显 |
| 语种错了 | 手动锁定目标，避免多人叠话和背景电视／音乐 |

“清空本次对话”会停止收音并清除当前历史与提词；旧的识别结果不会重新填回。需要继续聊天时，再点“开始收听”。关闭窗口会停止采集与界面更新；已经在本地执行的同步识别或已经发出的云端请求，不能保证从服务端取消，但其旧结果不会再显示。

## 8. 在自己的机器上完成首次验证

按顺序确认：离线三选项 → 一句真实文本 → 一段已知外语播放 → 中文按住录音 → VR 只读显示 → VR 点选 → 关闭和重新启动。

这些步骤用于隔离问题来源，不要求提供账号密钥给开发者。反馈问题时，说明失败步骤、错误提示、所用回复来源／ASR 来源以及 Windows 设备名称即可。
